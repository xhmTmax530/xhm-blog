# 策略模式
### 🌟 什么是策略模式？

**一句话解释：**

> 策略模式就是“把不同的做法（算法）封装成独立的类，让它们可以互相替换，而不影响主程序”。

就像你出门：

- 可以走路
- 可以骑车
- 可以开车
- 可以坐地铁

这些是不同的“策略”，你根据情况选择一种。程序里也一样，我们可以把每种“方式”封装起来，随时切换。

------

**✅ 场景举例：不同支付方式（微信、支付宝、银行卡）**

我们写一个简单的购物程序，支持多种支付方式，使用策略模式来实现。

### 💡 第一步：定义一个“支付策略”接口

```java
// 定义一个统一的“支付方式”接口
// 所有具体的支付方式（如微信、支付宝）都要实现这个接口
public interface PaymentStrategy {
    // 这个方法表示“执行支付”，具体怎么付由子类决定
    void pay(double amount);
}
```

> 🔍 解释：
>
> - `interface` 是 Java 中的“接口”，规定了一组行为（方法）。
> - 这里说：任何支付方式都必须有 `pay(double amount)` 方法。
> - 但不关心它内部怎么实现，只关心“能付钱”。

------

### 💡 第二步：实现具体的支付策略

#### 1. 微信支付策略

```java
// 微信支付的具体实现类
public class WeChatPayment implements PaymentStrategy {

    // 实现 pay 方法：用微信支付
    @Override
    public void pay(double amount) {
        System.out.println("✅ 使用微信支付：金额 " + amount + " 元");
        System.out.println("📱 扫码成功，正在扣款...");
        System.out.println("🔔 微信提示：支付成功！");
    }
}
```

> 🔍 解释：
>
> - `implements PaymentStrategy` 表示“我是一个支付方式”。
> - `@Override` 表示重写接口中的 `pay` 方法。
> - 这个类只做一件事：模拟用微信支付。

------

#### 2. 支付宝支付策略

```java
// 支付宝支付的具体实现类
public class AlipayPayment implements PaymentStrategy {

    // 实现 pay 方法：用支付宝支付
    @Override
    public void pay(double amount) {
        System.out.println("✅ 使用支付宝支付：金额 " + amount + " 元");
        System.out.println("📱 刷脸成功，正在扣款...");
        System.out.println("🔔 支付宝提示：支付成功，已到账！");
    }
}
```

> 🔍 和上面类似，只是换成了支付宝的逻辑。

------

#### 3. 银行卡支付策略

```java
// 银行卡支付的具体实现类
public class BankCardPayment implements PaymentStrategy {

    // 实现 pay 方法：用银行卡支付
    @Override
    public void pay(double amount) {
        System.out.println("✅ 使用银行卡支付：金额 " + amount + " 元");
        System.out.println("💳 插卡成功，输入密码...");
        System.out.println("🔔 银行系统提示：交易完成！");
    }
}
```

> 🔍 模拟刷卡支付流程。

------

### 💡 第三步：创建“购物车”类 —— 使用策略的人

```java
// 购物车类，它不关心用什么方式付款
// 它只负责“结算”，具体怎么付？交给用户传进来
public class ShoppingCart {

    // 声明一个支付策略对象（当前使用的支付方式）
    private PaymentStrategy paymentStrategy;

    // 构造方法：可以传入一种支付方式
    public ShoppingCart(PaymentStrategy paymentStrategy) {
        this.paymentStrategy = paymentStrategy;
    }

    // 方法：设置支付方式（允许中途更换）
    public void setPaymentStrategy(PaymentStrategy paymentStrategy) {
        this.paymentStrategy = paymentStrategy;
    }

    // 方法：执行结算
    public void checkout(double amount) {
        System.out.println("🛒 开始结算...");
        // 调用当前策略的 pay 方法
        paymentStrategy.pay(amount);
        System.out.println("🎉 结算完成，感谢购买！\n");
    }
}
```

> 🔍 关键点在这里：
>
> - `paymentStrategy` 是一个接口类型的变量，可以指向任意实现了它的类（微信、支付宝等）。
> - `checkout()` 方法不关心“怎么付”，只调用 `pay(amount)`。
> - 想换支付方式？调用 `setPaymentStrategy(...)` 就行！

------

### 💡 第四步：主程序测试

```java
// 主类，用来运行程序
public class Main {
    public static void main(String[] args) {

        // 创建各种支付策略对象
        PaymentStrategy wechat = new WeChatPayment();     // 微信
        PaymentStrategy alipay = new AlipayPayment();     // 支付宝
        PaymentStrategy bankcard = new BankCardPayment(); // 银行卡

        // 创建一个购物车
        ShoppingCart cart = new ShoppingCart(wechat);  // 默认用微信支付

        // 结算 199 元
        cart.checkout(199.0);

        // 更换为支付宝支付
        cart.setPaymentStrategy(alipay);

        // 再结算 88 元
        cart.checkout(88.0);

        // 再换成银行卡
        cart.setPaymentStrategy(bankcard);
        cart.checkout(299.0);
    }
}
```

### ✅ 为什么这是策略模式？核心在哪？

#### 🎯 核心代码是这三部分：

1. **定义统一接口：**

   ```java
   public interface PaymentStrategy {
       void pay(double amount);
   }
   ```

   > 所有策略都要遵守的“协议”。

2. **多个具体策略类：**

   ```
   class WeChatPayment implements PaymentStrategy { ... }
   class AlipayPayment implements PaymentStrategy { ... }
   ```

   > 每种方式独立封装，互不影响。

3. **上下文使用策略：**

   ```
   private PaymentStrategy paymentStrategy;
   public void checkout(double amount) {
       paymentStrategy.pay(amount);  // 动态调用
   }
   ```

   > 上下文（如 `ShoppingCart`）依赖接口，不依赖具体实现，可自由切换。

------

### ✅ 策略模式的好处

| 好处     | 说明                                                     |
| -------- | -------------------------------------------------------- |
| ✅ 易扩展 | 新增支付方式（如“刷脸支付”）只需新加一个类，不用改老代码 |
| ✅ 可替换 | 随时切换策略，比如用户选择不同支付方式                   |
| ✅ 解耦   | 购物车不用知道“微信怎么付”，只知道“调 pay 就行”          |

------

#### 🧠 类比生活

> 就像你去餐厅吃饭：
>
> - 你可以 **现金付、刷卡付、手机付**
> - 服务员不关心你怎么付，只说：“请付款”
> - 你拿出手机 or 钱包，完成动作
>
> 这就是“策略”：**同一件事，多种做法，自由切换**

------

### ✅ 总结一句话：

> **策略模式 = 把“算法”或“行为”封装成类，通过接口统一调用，让程序灵活可扩展。**
